# TS.43 in wwand-esim-transfer

The client in `esim_transfer/ts43.uc` follows GSMA TS.43 v13.0 (Service
Entitlement Configuration, 2026-02) as the open clients use it:
AOSP `frameworks/libs/service_entitlement` (Apache-2.0) and damonto/ts43-go
(GPL-3.0, read at 3bb3910, 2026-11-19; facts only, no code taken).

## Sequence

1. **Authenticate.** A request with `EAP_ID = 0<IMSI>@nai.epc.mnc<MNC3>.mcc<MCC>.3gppnetwork.org`
   and no operation.
   - The server answers with an `eap-relay-packet`, an EAP-AKA challenge
     (RFC 4187).
   - The router's USIM computes RES/CK/IK. This is `esim-transfer-card aka`:
     AUTHENTICATE `00 88 00 81` over wwand's APDU channel, on a logical
     channel to the USIM.
   - The response, with AT_RES and AT_MAC, is POSTed back to the bare URL.
   - The final body carries `TOKEN` (`token`, `Validity`).
2. **CheckEligibility.** Needs `OperationResult 1` and
   `PrimaryAppEligibility 1`.
3. **AcquireTemporaryToken**, only for transfer types 2, 9 and 11.
4. **ManageSubscription `operation_type 3`.** The `SubscriptionResult`
   decides what happens next:
   - 2: download (activation code)
   - 4: poll AcquireConfiguration
   - 1: the operator's web page (opened in a new window, then
     `ts43 continue`)
   - 8: a question (`ts43 accept|reject`)
   - 6: delete the source profile first (done through Release)
   - 3: done
   - 5 or 7: refused
5. **Install** (target = this router): download, enable, then
   ManageSubscription `operation_type 4` with the new ICCID, then poll until
   `ServiceStatus 1`.

A 511 re-authenticates once and repeats the step.

## Where this differs from ts43-go

- The server's **AT_MAC is verified** before RES is sent (RFC 4187 9.3).
  ts43-go does not verify it. Its published vector (from AOSP) carries a
  synthetic server MAC; `esim_transfer_lax_mac '1'` exists for test servers
  built that way.
- An unexpected EAP packet is answered with AKA-Client-Error, and a USIM that
  refuses AUTN with AKA-Authentication-Reject. ts43-go aborts instead.
- `encodedValue=` values are base64-decoded only when the prefix is present.
- The device identity is honest by default (`OWRT`, the modem model,
  `OS-OpenWrt`).

## Not covered

- EAP-AKA' (type 50).
- An embedded websheet: the operator's page cannot report back to LuCI across
  origins, so the user confirms by hand.
- The VoWiFi entitlement (ap2004).
- More than one Set-Cookie per response (see `esim_transfer/http.uc`).
